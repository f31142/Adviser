# 계정 복구와 데이터 운영

아래 명령은 실제 서버에서 그 서버의 `DATA_DIR`을 대상으로 실행합니다. GitHub 파일 삭제·수정이나 재배포만으로 고객 데이터가 초기화되지는 않습니다.

## 비밀번호 복구

관리자 계정도 데이터베이스에 저장됩니다. 초기 `ADMIN_PASSWORD`를 바꾸는 것은 기존 비밀번호를 재설정하지 않습니다. 운영자가 본인 확인을 마친 후 CLI를 사용합니다.

Bash 예시 (입력은 화면에 표시하지 않음):

```sh
read -rs -p '새 비밀번호: ' RESET_PASSWORD
export RESET_PASSWORD
npm run admin -- reset-password ADMIN
unset RESET_PASSWORD
```

특정 고객을 복구하려면 마지막 인자를 그 고객 이메일로 바꿉니다. 10~128자의 새 비밀번호를 요구하고, 해당 사용자의 기존 세션을 전부 폐기합니다. 비밀번호 원문을 명령 인자나 Git에 넣지 않습니다. 고객에게 새 비밀번호를 전달할 안전한 경로는 운영자가 마련해야 합니다. 이메일 소유 확인·자동 재설정 메일은 제공하지 않습니다.

## 고객 계정과 작업 초기화

**복구 불가능한 삭제입니다. 고객·신청·설문·채팅·첨부·결제 기록과 모든 로그인 세션이 삭제됩니다. 관리자 계정 및 서비스 가격·계좌·안내 설정은 유지됩니다.** 결제업체의 실제 결제나 은행 거래를 취소하지는 않습니다. 정산 및 보존할 기록을 먼저 처리하세요.

1. 웹 서버를 중지하고 새 요청을 막습니다.
2. `DATA_DIR` 전체를 백업합니다. SQLite DB와 파일을 같은 시점으로 보관합니다.
3. 대상 환경과 백업을 확인한 후 아래 명령을 실행합니다.

```sh
npm run admin -- reset-customers --confirm=DELETE-ALL-CUSTOMERS
```

4. 서버를 다시 시작하고 ADMIN 로그인을 확인합니다.

확인 중인 온라인 결제가 남아 있으면 초기화를 거부합니다. DB 삭제는 트랜잭션으로 처리하며, 이후 파일을 정리합니다. 파일 삭제 도중 실패했다면 같은 명령을 재실행해 남은 파일을 정리합니다. 이 도구를 이번 코드 작성 과정에서 기존 운영 데이터에 실행하지 않았습니다. 테스트는 임시 DB에서만 진행했습니다.

## 백업과 복원

서버를 중지한 상태에서 `DATA_DIR` 전체를 접근이 통제되는 저장소에 복사합니다. 민감한 고객 자료가 포함되므로 GitHub나 공개 파일 공유에 올리지 않습니다. 복원할 때도 서버를 중지하고 DB와 `files/`를 함께 복원한 뒤 시작합니다. 소스 코드는 해당 DB 마이그레이션과 호환되는 커밋을 사용합니다.

Render 디스크 스냅샷만으로 업무 백업 정책을 대신하지 말고, 정해진 주기와 보관 기간으로 별도 백업 및 복원 점검을 운영하세요. 안내 문구를 바꾸는 것만으로 자료가 자동 삭제되지는 않습니다. 종료된 작업은 관리자 화면의 첨부 자료 삭제 기능으로 정리할 수 있습니다.
