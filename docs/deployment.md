# 외부 서버 배포

GitHub `main`이 원본이고, 이 저장소에는 Sites 호스팅 설정이나 Sites 인증 코드가 없습니다. 실제 고객 데이터는 새 서버의 별도 영구 디스크에 저장합니다.

## Render

루트의 `render.yaml`은 다음 배포를 정의합니다.

| 항목        | 설정                                    |
| ----------- | --------------------------------------- |
| 원본        | `f31142/Adviser`, `main`                |
| 서버        | Node.js 24, 단일 인스턴스               |
| 지역        | Singapore                               |
| 컴퓨트      | `0.5c-512mb` (유료)                     |
| 영구 디스크 | 1GB, `/opt/render/project/src/data`     |
| 배포 조건   | main의 CI 검사 통과                     |
| 빌드        | `npm ci --include=dev && npm run build` |
| 시작        | `npm start`                             |
| 상태 확인   | `/healthz`                              |

Render 계정과 GitHub 저장소를 연결해 Blueprint를 생성합니다. **컴퓨트와 디스크에 비용이 발생하므로 생성 화면의 금액을 확인한 뒤 배포합니다.** 이 파일을 커밋하는 것만으로 유료 리소스가 생성되지는 않습니다.

초기 설정에서 `ADMIN_PASSWORD`를 비밀값으로 입력합니다. 운영 DB가 만들어지면 기존 사용자와 세션은 새 배포로 초기화되지 않습니다. 기본 주소에는 Render가 제공하는 `RENDER_EXTERNAL_URL`을 사용합니다. 별도 도메인을 연결할 때는 `APP_URL=https://실제도메인`을 지정하고 그 주소로 접속합니다. 주소가 다르면 Origin 검사 때문에 변경 요청이 거부됩니다.

소스는 재배포되어도 `DATA_DIR`은 유지되어야 합니다. 무료 임시 파일시스템에 운영 DB를 두지 마세요. 디스크가 연결된 서비스는 재배포 중 짧은 중단이 있을 수 있습니다. 정기적으로 DB와 파일을 함께 백업합니다.

공식 안내: [Blueprint 설정](https://render.com/docs/blueprint-spec), [영구 디스크](https://render.com/docs/disks), [기본 환경변수](https://render.com/docs/environment-variables).

## Docker 또는 기존 서버

```sh
cp .env.example .env
# APP_URL, ADMIN_PASSWORD를 직접 설정
# 로컬 확인: APP_URL=http://localhost:3000
docker compose up --build -d
```

Compose는 `adviser-data` 볼륨에 DB와 첨부를 보관하고 로컬 3000번 포트를 엽니다. 공개 운영은 HTTPS 역방향 프록시를 연결하고 `APP_URL`을 실제 주소로 지정합니다. 기존 서버에 직접 설치하면 Node.js 24에서 `npm ci`, `npm run build`, `npm start`를 실행합니다. 서비스 관리자를 이용해 재시작하도록 구성합니다.

단일 Node 프로세스만 실행합니다. PM2 cluster나 여러 복제본을 같은 DB에 연결하지 않습니다. `TRUST_PROXY=true`는 최종 프록시가 X-Forwarded-For를 설정/추가하도록 통제된 환경에서만 사용합니다.

## 결제 연결

계좌이체는 관리자 운영 설정에서 은행·계좌번호·예금주를 입력합니다. 고객이 이체 후 확인 요청을 보내고, 관리자가 실제 입금을 확인해 완료 처리합니다. 버튼을 누르는 것만으로 송금이 실행되지는 않습니다.

토스페이먼츠는 이 앱의 SDK `payment()`에 맞는 **API 개별 연동 키**를 사용합니다. 두 환경변수를 같은 상점·모드로 설정합니다.

| 환경변수          | 저장 위치                                             |
| ----------------- | ----------------------------------------------------- |
| `TOSS_CLIENT_KEY` | 서버 환경설정; 필요한 결제 요청에서 클라이언트에 전달 |
| `TOSS_SECRET_KEY` | 서버 비밀 환경설정; 브라우저·Git에 넣지 않음          |

키가 없으면 카드·간편결제 버튼은 활성화되지 않습니다. 테스트 키는 실제 과금 없는 테스트임을 화면에 표시합니다. 먼저 가맹점 테스트 환경에서 승인·실패·새로고침·모바일 복귀·전액 취소를 확인하고 라이브 키로 전환합니다. 간편결제 종류는 가맹점 계약과 결제 창 제공 범위에 따릅니다.

결제 후 확인이 중단됐다면 마이페이지의 해당 신청에서 **온라인 결제 상태 확인**을 누릅니다. 온라인 환불은 결제업체 관리자 화면에서 진행하고 같은 버튼으로 사이트에 전액 취소를 반영합니다. 부분 환불은 관리자와 수동 정산하며 자동 완료로 기록하지 않습니다.

토스 공식 문서: [키와 SDK 설정](https://docs.tosspayments.com/sdk/v2/js/environment), [결제창](https://docs.tosspayments.com/sdk/v2/js/payment), [승인·조회·취소 API](https://docs.tosspayments.com/reference).

## 공개 후 확인

고객 가입·로그인·로그아웃, 두 서비스의 신청, 첨삭 파일 필수 여부, 관리자 승인 전 결제 차단, 승인·보완·반려, 입금 확인, 채팅·첨부·결과물·수정 요청을 별도 테스트 계정으로 확인합니다. 다른 계정의 파일이 노출되지 않는지와 재배포 후 데이터가 유지되는지도 확인합니다. 실제 운영할 환불·보관 안내를 입력한 후 고객을 받습니다.
