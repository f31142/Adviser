# 기존 구조와 인증

이 문서는 이전 개발 기록과 Sites 조회 결과를 바탕으로 작성했습니다. 원본 파일을 아직 회수하지 못했으므로 현재 GitHub 저장소의 코드로 검증된 설명은 아닙니다.

## 구성 요소

| 구성 요소 | 기록된 구현 |
| --- | --- |
| 언어 | TypeScript |
| 화면 | React, Vinext 기반 Next 호환 앱 구조 |
| 빌드 | Vite, pnpm |
| API | 서버의 workspace API 및 파일 API |
| 계정·신청·채팅 데이터 | Cloudflare D1 |
| 비공개 파일 | Cloudflare R2 |
| 기존 호스팅·소스 보관 | ChatGPT Sites |
| 새 소스 관리 목적지 | f31142/Adviser |

정확한 의존성 버전과 실행 명령은 원본 package.json 및 잠금 파일을 가져온 후 확정합니다.

## 두 종류의 로그인

기존 사이트에는 Sites에서 제공하는 사이트 접근 제어와, Adviser 내부의 고객·관리자 로그인이 별도로 존재합니다.

Sites 소유자·방문자 설정은 Adviser의 고객 계정 데이터와 다릅니다. Adviser 계정을 초기화해도 사용자의 ChatGPT 계정이나 Sites의 소유자 설정을 삭제해서는 안 됩니다.

## 비밀번호와 세션 처리

기존 구현 기록은 다음과 같습니다.

- 비밀번호는 PBKDF2-SHA256, 100,000회 반복, salt를 사용해 해시합니다.
- 관리자 초기 비밀번호 해시는 서버의 ADMIN_PASSWORD_HASH 비밀 설정에서 읽습니다.
- 관리자 계정이 없을 때 관리자 로그인 경로에서 초기 계정을 만드는 처리가 있습니다.
- 서버는 세션 토큰의 SHA-256 해시를 DB에 저장합니다.
- 브라우저의 인증 쿠키에는 HttpOnly, Secure, SameSite=Lax가 적용됩니다.
- 세션 유효 기간은 7일로 설정되어 있습니다.
- 로그아웃 시 해당 세션을 삭제합니다.
- 비밀번호 변경 시 해당 사용자의 모든 세션을 삭제합니다.
- 회원가입·로그인 등에는 요청 제한이 적용됩니다.

원본 회수 후 실제 토큰 생성 방식, 쿠키 이름, SQL과 만료 처리까지 다시 확인합니다. 이 문서만으로 보안 검증 완료를 주장하지 않습니다.

## 요청 흐름

브라우저가 인증 쿠키를 포함해 API를 호출하면 서버는 세션 토큰 해시와 만료 시간을 확인하고 사용자를 식별합니다. 신청·채팅·파일 접근 시 해당 신청의 소유자 또는 관리자 여부를 검사합니다. 화면에서 메뉴를 숨기는 것만으로 권한을 판단하지 않습니다.

기록상 요청 출처와 Sec-Fetch-Site를 검사하는 처리도 있습니다. DB 수정과 상태 변경은 API의 역할·상태 검증을 통과해야 합니다.

## 신청 상태

Sites 저장 버전 2에는 다음 업무 흐름 변경이 기록되어 있습니다.

| 상태 | 의미 |
| --- | --- |
| draft | 신청서 작성 중 |
| approval | 관리자 검토 대기 |
| application_supplement | 신청 내용 보완 요청 |
| approved | 승인 완료, 결제 가능 |
| received | 결제 확인 후 작업 접수 |
| working | 작업 중 |
| review | 고객 검토 |
| complete | 작업 완료 |

기존의 payment 상태로 생성된 신청에 대한 호환 처리와 취소·환불 관련 상태도 있습니다. 전체 전이 규칙은 원본 API를 기준으로 대조해야 합니다.

## 데이터베이스

Sites DB 조회에서 확인한 바인딩은 DB이며 테이블 이름은 다음과 같습니다.

| 테이블 | 기록된 목적 |
| --- | --- |
| users | 고객과 관리자 계정 |
| sessions | 로그인 세션 |
| orders | 신청, 설문, 금액 및 진행·결제 상태 |
| messages | 신청별 채팅 |
| files | 첨부 파일과 결과물의 메타데이터 |
| notices | 사이트 내 알림 |
| settings | 서비스 가격과 운영 설정 |
| limits | 요청 제한 |

정확한 컬럼, 인덱스, 외래키는 원본 스키마를 가져온 뒤 문서에 반영합니다. 실제 행 데이터는 이 저장소에 복사하지 않습니다.

## 파일 처리

기존 기록상 파일은 비공개 R2 버킷에 보관하고, D1에는 메타데이터를 저장합니다. 임의 파일 ID를 사용하고 소유자·관리자 권한을 확인한 뒤 다운로드합니다.

기존 제한은 파일당 15MB, 신청당 최대 30개, PDF·DOC·DOCX·HWP·HWPX·TXT 형식입니다. 원본 서류는 결제 전 첨부할 수 있고, 관리자 결과물은 결제 확인 후 등록하도록 되어 있습니다.
