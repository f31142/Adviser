# 이전 및 계정 초기화 작업 상태

## 현재 확인된 내용

- GitHub 목적지는 f31142/Adviser입니다.
- 문서 작성 시 GitHub 연결의 저장소 읽기·쓰기 권한이 확인되었습니다.
- 기존 사이트와 DB 조회는 가능했습니다.
- 기존 소스는 Sites에 저장되어 있으며 GitHub에는 아직 가져오지 못했습니다.
- 개발 환경은 exec-server 초기 연결 대기 중 시간 초과 오류를 보고했습니다.
- 이 대화에 파일 읽기·편집·셸 실행 도구가 제공되지 않고 있습니다.
- 현재 Sites DB 도구는 조회 전용입니다.
- GitHub의 파일 생성·수정 기능은 사용할 수 있어 이전 준비 문서를 먼저 보존했습니다.

전체 서비스 장애 공지와 개별 개발 환경의 연결 실패 사이의 직접적인 인과관계는 확인되지 않았습니다. GitHub 연결이 정상이라는 사실만으로 개발 환경 복구나 운영 DB 변경 가능 여부를 판단하지 않습니다.

| --- | --- |
| 요구사항과 기존 구조 문서 보존 | 완료 |
| Sites 원본 버전 정보 보존 | 완료 |
| 원본 코드·정적 자산·잠금 파일 이전 | 미완료 |
| 이전된 코드의 실행·빌드 검증 | 미완료 |
| 계정 초기화 구현 | 미완료 |
| 운영 계정 초기화 실행 | 미완료 |
| 관리자 승인 후 결제 흐름의 재게시 | 미완료 |

현재의 문서 커밋은 운영 사이트나 데이터베이스를 변경하지 않습니다.

## 원본 회수 후 이전 순서

1. Sites 원본 저장소 또는 원본 프로젝트 압축 파일의 전체 내용을 확보합니다.
2. source-provenance.json의 저장 버전과 커밋을 기준으로 원본을 대조합니다. 버전 2에는 관리자 승인 후 결제하는 변경이 포함된 것으로 기록되어 있습니다.
3. 소스·정적 자산·패키지 잠금 파일·DB 스키마·기존 검증 코드를 가져옵니다.
4. 비밀값, 실제 고객 데이터, 로컬 DB, 업로드 파일, 빌드 캐시가 포함되지 않았는지 확인합니다.
5. 기존 Sites 프로젝트 ID와 DB·R2 바인딩을 유지합니다. 계정 초기화를 위해 새 사이트나 새 DB를 만드는 방식으로 대체하지 않습니다.
6. 원본 README와 이 저장소의 이전 기록을 정리하고 실행 방법을 실제 패키지 설정에 맞춰 문서화합니다.
7. GitHub에 원본 기준 커밋을 저장한 다음 계정 초기화 변경을 별도 커밋으로 작성합니다.

## 계정 초기화 변경의 목표

사용자는 기존 Adviser 계정 정보 초기화와 그 이후 게시를 요청했습니다. 이 권한은 이미 제공되었지만 실제 실행은 완료되지 않았습니다.

구현 시 다음을 확인합니다.

- 기존 사용자 계정과 모든 로그인 세션을 초기화합니다.
- 초기 관리자 로그인은 기존 서버의 비밀 설정을 이용해 복구합니다. 평문 비밀번호를 코드에 넣지 않습니다.
- 신청·채팅·파일·알림과 사용자 계정 사이의 관계를 원본 스키마에서 확인합니다.
- 계정 삭제에 따라 필요한 연관 데이터 처리는 데이터 관계와 요청 범위를 검토한 뒤 구현합니다. 이 문서는 운영 데이터의 일괄 삭제 SQL이 아닙니다.
- Sites의 소유자 접근 설정, 서비스 가격과 운영 설정은 계정 정보와 구분합니다.
- 초기화 작업은 인증된 관리 경로에서 의도적으로 한 번 실행되어야 합니다. 재배포나 일반 요청 때마다 자동 삭제하는 처리를 추가하지 않습니다.
- DB 변경은 가능한 경우 원자적으로 처리하며, R2 파일 처리와의 일관성도 검토합니다.
- 운영 데이터에 적용하기 전에 테스트 DB에서 권한, 세션 무효화, 관리자 복구, 데이터 관계를 검증합니다.

초기화 완료를 확인한 다음 저장된 관리자 승인 후 결제 흐름을 게시하고 실제 배포 상태를 확인합니다.

## 현재 필요한 입력

원본 프로젝트 전체 파일에 대한 접근이 필요합니다. 현재 코드 내용을 읽을 수 없어 수정안을 기존 구현에 정확히 적용할 수 없습니다. 원본이 확보되기 전에는 이 문서만으로 기존 소스 전체 이전이나 계정 초기화 수정을 완료했다고 표시하지 않습니다.
