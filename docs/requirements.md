# Adviser 요구사항

이 문서는 이 대화에서 확정된 요구사항을 보존한 것입니다. 현재 구현 범위와 외부 연결이 필요한 항목은 README에 정리합니다.

## 서비스

사촌이 운영하는 유료 서류 첨삭·작성 서비스를 고객 신청, 관리자 검토, 결제, 결과 전달, 피드백까지 관리합니다. 여기서 “서류”는 자기소개서 등 제출 문서를 통칭합니다.

| 서비스         | 신청 자료                                         |
| -------------- | ------------------------------------------------- |
| 기존 서류 첨삭 | 작성한 서류 첨부, 제출 기관, 비고, 공통 설문      |
| 새 서류 작성   | 제출 기관, 비고, 공통 설문. 기존 서류 첨부는 선택 |

두 서비스 모두 초기 가격은 100,000원입니다. 관리자가 서비스별 가격을 수정하며, 기존 신청의 금액은 신청 당시 기록을 유지합니다.

## 신청과 결제 순서

1. 고객이 이메일·비밀번호로 가입하고 로그인합니다.
2. 서비스를 선택하고 설문을 작성합니다. 첨삭 서비스는 원본 서류를 첨부합니다.
3. 고객이 신청서를 제출합니다.
4. 관리자가 신청 내용과 서류를 검토하고 승인하거나 보완을 요청합니다.
5. 보완 요청을 받은 고객은 신청서를 수정해 다시 제출합니다.
6. 승인된 신청에 대해 고객이 결제합니다.
7. 결제가 확인되면 관리자가 첨삭 또는 작성을 진행합니다.
8. 관리자와 고객이 신청별 채팅으로 피드백을 주고받습니다.
9. 관리자가 결과물을 전달하고, 고객이 검토하거나 정해진 범위에서 수정을 요청합니다.
10. 관리자가 작업 완료로 표시하면 고객은 수정 요청 또는 **완료 확인 · 작업 종료**를 선택합니다. 고객이 확정한 작업은 종료되며 기존 파일과 대화 기록은 계속 확인할 수 있습니다.

이 순서는 기존의 결제 선행 방식에서 변경된 최종 요구사항입니다. 관리자 승인 전 결제 요청과 결제 확인을 서버에서도 제한해야 합니다.

## 공통 설문

- 제출 기관
- 지원 직무
- 학력
- 경력
- 주요 경험
- 작성 문항과 각 문항의 글자 수
- 희망 마감일
- 비고 및 요청사항

기존 구현 기록에는 신청 동의와 필요한 항목의 서버 검증이 포함됩니다. 비고를 제외한 공통 항목은 필수이며, 신청 시 서류 열람 동의를 받습니다.

## 고객 계정과 권한

- 이메일·비밀번호로만 회원가입합니다. 간편로그인은 제외합니다.
- 회원가입 비밀번호는 8~16자이며 특수문자를 최소 1개 포함합니다. 비밀번호 변경과 복구에도 동일한 규칙을 적용하며 기존 계정 로그인은 유지합니다.
- 로그인 화면은 하나이며, 관리자 안내 문구나 별도 관리자 로그인 메뉴를 표시하지 않습니다. 입력한 계정 정보로 역할을 판별합니다.
- 자신의 신청 목록, 진행 상태, 결제 정보, 채팅, 첨부 파일과 결과물을 확인합니다.
- 다른 고객의 신청·채팅·파일에는 접근할 수 없어야 합니다.
- 로그인한 상태에서 비밀번호를 변경하고 로그아웃할 수 있어야 합니다.
- 이메일 인증과 비밀번호 찾기 메일 발송은 기존 구현 기록상 미구현입니다.

## 관리자 계정과 권한

- 관리자 로그인 ID는 ADMIN입니다.
- 로그인 후 서비스 신청과 새 신청 버튼을 표시하지 않습니다. 전체 작업·회원 관리·운영 설정에서 관리 업무를 수행합니다.
- 관리자 비밀번호와 해시는 GitHub 문서나 코드에 기록하지 않습니다.
- 모든 신청을 확인하고 조건별로 찾을 수 있습니다.
- 신청을 승인하거나 보완을 요청합니다.
- 서비스별 가격과 운영 설정을 변경합니다.
- 입금 확인, 작업 진행 상태 변경, 결과물 전달, 고객 피드백 응대를 수행합니다.
- 취소와 환불 처리 상태를 관리합니다.
- 회원 관리 화면에서 고객을 이름·이메일로 검색하고 계정을 삭제합니다. 대상 이메일을 다시 입력해야 삭제되며, 관리자 계정은 삭제할 수 없습니다.
- 삭제 시 계정의 이름·이메일·비밀번호와 모든 로그인 세션을 제거합니다. 기존 신청서·채팅 내용·첨부·결제 기록은 관리자에게 ‘삭제된 회원’으로 남습니다. 같은 이메일로 다시 가입하더라도 이전 계정의 작업에 접근할 수 없습니다.

관리자는 사유를 입력해 검토 중인 신청을 반려할 수 있습니다. 반려된 신청은 결제할 수 없습니다.

## 결제

사용자는 카드·간편결제 등 결제대행사를 통한 결제와 계좌이체를 함께 제공하기를 원합니다.

- 계좌이체: 관리자가 입금 계좌를 설정하고 실제 입금을 확인한 뒤 결제 완료로 처리합니다.
- 결제대행사 결제: 가맹점 연동과 실제 결제 검증이 필요합니다. 토스페이먼츠 어댑터를 구현했으며, 가맹점 키가 없으면 준비 중으로 표시합니다.
- 환불: 계좌이체는 수동 환불 후 기록하며, 온라인 결제는 결제업체 전액 취소를 서버 조회로 확인합니다.
- 금액은 서버에서 서비스 설정을 기준으로 확정하며, 고객이 임의로 변경한 금액을 신뢰하지 않습니다.

## 피드백과 운영 기능

- 신청별 고객–관리자 채팅은 새로고침 없이 상대 메시지를 반영합니다.
- 새로고침과 브라우저 뒤로 가기에서도 현재 메뉴와 작업 상세 화면을 복원합니다.
- 원본 첨부와 관리자 결과물 전달
- 수정 요청 횟수 관리
- 진행 상태 및 사이트 내 알림
- 취소 요청과 환불 상태 관리
- 종료된 작업의 파일 정리

이메일·문자 알림은 기존 구현 기록상 연결되지 않았습니다.

## GitHub 중심 운영

기존 사이트는 사용자가 삭제했습니다. GitHub main을 원본으로 독립 실행 사이트를 구성하고 새 DB에서 시작합니다. 소스·설정 예시·스키마·문서를 저장하며 실제 고객 데이터와 비밀값은 제외합니다. 외부 호스팅 및 결제업체 연결은 별도 단계입니다.
